# 買取・販売の決定値から明細を作る

## 範囲と取引方向

- このスキルの「販売」はステラからシェアソーシング契約企業への卸販売を指す。最終顧客への小売販売実績は数量判断の根拠として使う。
- 会社・取引方向ごとに明細を分ける。ステラから契約企業への販売は「販売・請求明細（下書き）」、契約企業からステラへの買取は「買取・支払明細（下書き）」とする。買取をステラから相手への請求と取り違えない。
- 買取側の正式帳票が取引先発行の請求書か、合意済みの仕入明細書等かは既存運用・見本で確認する。相手名義の正式請求書を勝手に発行しない。売買を自動相殺しない。
- 数量決定から明細作成まで依頼された場合は、確定した取引データから下書きまで一続きで作成する。判断だけの依頼では判定結果まで、模擬依頼では「試算・未発注・未請求」と明記した参考明細までとする。
- 正式発行・採番・会計登録・送付・支払実行は下書き作成と区別する。ユーザーが依頼した範囲のみ行い、このスキルの改訂を実際の発行・送付依頼と解釈しない。

## 決定値の引継ぎ

1. 商品選定時に会社、取引方向、取引ID、ロットID、商品名、ASIN/JAN、販売単位とセット個数、数量、単価、金額、決定理由を保存する。状態は「候補／保留／確定／取引実施済／明細作成済／発行済／送付済」を区別する。
2. 明細には確定分だけを渡す。候補・保留・数量0を請求対象にしない。部分確定なら確定分だけを明細化する。実施済みと確定予定は混同せず、契約上の請求時点を確認する。
3. 買取単価は本文のFIFOで特定したロットの他社元仕入単価×1.03切上げ。すでに買戻し単価へ換算済みの値に再度1.03を掛けない。販売単価は合意した卸価格を使い、買戻しの3％ルールを販売価格の決定に流用しない。
4. ロットや単価が違う行は分け、数量×単価の計算根拠を維持する。仕入れ判定で使う実物個数と、帳票の箱・セット等の請求単位を明示して換算する。

## 下書きの作成と照合

- 既存テンプレート・過去の同方向の明細があれば、その形式を優先する。なければ会社・取引方向ごとに、商品、JAN/ASIN、数量、単位、単価、金額、合計の簡潔な明細を作る。根拠や内部判断は相手向け明細と別に保持する。
- 発行主体の法人名、相手先、取引日／対象期間、税抜・税込、適用税率、端数処理、送料等の付随費用、支払条件を既存の合意資料で確認する。登録番号・振込先・税率・支払期日・請求番号を推測しない。不明は要確認とし、正式な請求総額を確定しない。
- 明細の取引IDと、決定記録・出荷／入庫記録・仕入帳等の対応行を結び付ける。同じ取引から下書きを作り直す場合は版を更新し、別の請求として増やさない。正式発行済みの明細を無断上書きしない。
- 商品別数量、単価、行金額、税区分別集計、付随費用、総額を照合する。確定数量と実際の出荷・入庫数が違う場合は、合意した請求基準を確認するまで該当行を保留する。
- 納品する際は「数量案」「確定取引」「明細下書き」「正式発行済み」「送付済み」のどこまで完了したかを報告する。下書き作成を請求完了や支払完了と説明しない。
